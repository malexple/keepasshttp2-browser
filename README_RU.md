# KeePassHttp2 Browser

Минимальное браузерное расширение для KeePassHttp2. Оно подключается к локальному WebSocket-серверу KeePassHttp2, запрашивает учётные данные для URL активной вкладки и подставляет выбранные логин и пароль в форму сайта.

> Статус: разработка / proof of concept. Расширение загружается в браузер как распакованное и пока не предназначено для публикации в магазине расширений.

## Возможности

- Локальное WebSocket-подключение к KeePassHttp2.
- Шифрованный протокол в стиле KeePassXC-Browser:
  `change-public-keys` → `test-associate` → `associate` → `get-logins`.
- Генерация и постоянное хранение пары ключей идентификации в `browser.storage.local`.
- Диалог Allow/Deny в KeePass при первом подключении браузера.
- Поиск записей KeePass, соответствующих URL активной вкладки.
- Отображение найденных записей в popup расширения.
- Подстановка логина и пароля выбранной записи в текущую страницу.
- Форма входа **не отправляется автоматически**.

## Требования

- Windows с установленным [KeePass](https://keepass.info/).
- Установленный и включённый плагин KeePassHttp2.
- Node.js и npm.
- Vivaldi, Google Chrome, Microsoft Edge или другой Chromium-браузер.

## Настройка KeePassHttp2

1. Запустите KeePass.
2. Откройте и разблокируйте базу данных с нужными записями.
3. Убедитесь, что KeePassHttp2 включён: `Tools` → `Plugins`.
4. Откройте `Tools` → `KeePassHttp2 Options...`.
5. Посмотрите настроенный порт прослушивания.

Порт в KeePassHttp2 и в браузерном расширении обязан быть **одинаковым**.

По умолчанию браузерное расширение использует порт `19455` в файле `lib/storage.ts`:

```ts
port: 19455,
```

Если KeePassHttp2 работает на другом порту, например `19456`, измените значение до сборки:

```ts
port: 19456,
```

После изменения порта по умолчанию удалите и загрузите расширение заново или очистите хранилище расширения. Иначе браузер может продолжать использовать ранее сохранённый порт.

## Установка зависимостей

В каталоге браузерного расширения выполните:

```powershell
cd D:\project\nodejs\keepasshttp2-browser
npm install
```

## Сборка расширения

```powershell

```

WXT создаст распакованное расширение в каталоге:

```text

```

Проверить TypeScript без сборки:

```powershell
npm run compile
```

## Установка в Vivaldi

1. Откройте Vivaldi.
2. Введите в **адресную строку браузера**, а не в PowerShell:

   ```text
   vivaldi://extensions/
   ```

3. Включите **Developer mode / Режим разработчика**.
4. Нажмите **Load unpacked / Загрузить распакованное**.
5. Выберите каталог:

   ```text
   D:\project\nodejs\keepasshttp2-browser\.output\chrome-mv3
   ```

6. При необходимости закрепите иконку расширения на панели браузера.

После каждого `npm run build` откройте `vivaldi://extensions/` и нажмите кнопку обновления `↻` у расширения.

## Первое сопряжение

1. Откройте обычную страницу `http://` или `https://`. Для проверки autofill откройте страницу с настоящей формой входа.
2. Нажмите иконку расширения.
3. Popup подключится к KeePassHttp2.
4. При первом подключении KeePass покажет диалог сопряжения.
5. Укажите понятное имя, например:

   ```text
   Vivaldi KeePassHttp2
   ```

6. Нажмите **Allow / Разрешить**.

Плагин сохранит постоянный публичный ключ браузерного расширения в текущей открытой базе KeePass. При следующих подключениях используется `test-associate`, поэтому окно Allow/Deny появляться не должно.

## Использование

1. Откройте страницу с формой входа.
2. Нажмите иконку расширения.
3. Popup покажет записи KeePass, URL которых имеют тот же hostname, что и активная вкладка.
4. Нажмите нужную запись.
5. Расширение заполнит поля логина и пароля.
6. Проверьте подставленные данные и сами нажмите кнопку входа на сайте.

Расширение специально не выполняет автоматический submit формы.

## Структура проекта

```text
entrypoints/
  background.ts          Клиент протокола и связь с KeePassHttp2
  content.ts             Код для внедрения в страницу и заполнения формы
  popup/
    index.html           Разметка popup
    main.ts              UI popup и выбор записи
lib/
  protocol.ts            Crypto_box-хелперы TweetNaCl
  storage.ts             Постоянные данные браузера: ключи, ID сопряжения, порт
wxt.config.ts            Конфигурация WXT и manifest
```

## Как работает autofill

Popup расширения не может напрямую изменять DOM открытого сайта. После выбора записи popup использует права `activeTab` и `scripting`, чтобы внедрить `entrypoints/content.ts` в активную вкладку.

Content script:

1. Находит первое доступное поле пароля.
2. Ищет перед ним текстовое поле, поле email или телефон как поле логина.
3. Устанавливает выбранные логин и пароль.
4. Генерирует события `input` и `change`, чтобы формы на React, Vue, Angular и аналогичных фреймворках увидели изменение.

Это намеренно простая эвристика. Некоторые сайты используют многошаговый вход, iframe, Shadow DOM, нестандартные компоненты или необычный порядок полей. Для них в будущем может потребоваться отдельная обработка.

## Разрешения браузера

В manifest расширения используются следующие права:

| Разрешение | Назначение |
|---|---|
| `storage` | Хранение ключей идентификации, ID сопряжения и порта в профиле браузера |
| `activeTab` | Временный доступ к активной вкладке после явного клика пользователя по расширению |
| `scripting` | Внедрение content script в активную вкладку для autofill |

## Диагностика

### Popup показывает `connection failed - is KeePassHttp2 running?`

Возможные причины:

- KeePass не запущен.
- Плагин KeePassHttp2 не загрузился.
- База данных KeePass закрыта или заблокирована.
- Порт плагина не совпадает с портом расширения.

Проверьте `keepasshttp2.log` рядом с DLL плагина.

### Popup долго показывает `Connecting to KeePassHttp2...`

Проверьте service worker расширения:

1. Откройте `vivaldi://extensions/` или `edge://extensions/`.
2. Включите Developer mode.
3. У расширения нажмите `service worker` или `Inspect views`.
4. Откройте вкладку Console.
5. Повторите действие в popup и посмотрите ошибки.

Также проверьте `keepasshttp2.log`.

### В логе есть `test-associate: missing id/key`

На первом подключении пустой ID сопряжения является нормальным: браузер ещё не знает ID, потому что не был сопряжён с KeePass. В этом случае KeePassHttp2 должен вернуть обычный зашифрованный ответ `success: "false"`, после чего расширение отправит `associate` и KeePass покажет окно Allow/Deny.

Если вместо ответа сервер пишет reject и молчит, обновите плагин до версии, где пустой ID первого подключения обрабатывается как ожидаемый случай.

### Popup показывает `No matching entries for this site.`

Текущая логика сопоставляет hostname. Например, запись с URL:

```text
https://example.com/login
```

соответствует странице:

```text
https://example.com/...
```

но не обязательно странице с другим hostname, например:

```text
https://accounts.example.com/...
```

### Popup показывает `Password field not found on this page.`

- Убедитесь, что вы открыли именно страницу с формой логина.
- После обновления расширения обновите страницу с формой через `Ctrl+R`.
- Нельзя выполнять autofill на внутренних страницах браузера: `vivaldi://...`, `edge://...`, `chrome://...`.
- Сайт может использовать iframe, Shadow DOM, многошаговый вход или нестандартные поля.

### В браузере всё ещё виден экран WXT starter

Popup WXT должен собираться из файлов:

```text
entrypoints\popup\main.ts
entrypoints\popup\index.html
```

Не редактируйте содержимое `.output`: WXT перезаписывает его при каждой сборке.

## Разработка

Команда:

```powershell
npm run dev
```

запускает режим разработки WXT и обычно пытается автоматически открыть Google Chrome. Если Chrome не установлен, WXT может успешно собрать расширение, а затем завершиться с ошибкой:

```text
No Chrome installations found.
```

Для Vivaldi или Edge используйте:

```powershell
npm run build
```

и вручную загружайте каталог `.output\chrome-mv3` как unpacked extension.

## Безопасность

- KeePassHttp2 должен слушать только локальный интерфейс.
- После `change-public-keys` данные протокола шифруются с помощью NaCl `crypto_box`.
- Новая идентичность браузера требует явного подтверждения в KeePass.
- Ключ сопряжения хранится в текущей базе KeePass.
- Не открывайте WebSocket-порт KeePassHttp2 в локальную сеть или интернет.
- Autofill запускается только после явного выбора записи пользователем.
- Расширение не отправляет форму автоматически.
